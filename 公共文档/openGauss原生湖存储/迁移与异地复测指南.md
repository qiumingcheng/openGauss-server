以下步骤适用于一台新的 Linux x86_64 机器或云端编译容器，约定工作区根目录 `$CPP_WORKSPACE`（下用 `$WS` 简写），保持与 `AGENTS.md` §0.1 一致的目录结构。

### 4.1 第 0 步：准备基础环境与源码树

1. 安装系统依赖与工具：`git`、`make`、`ninja-build`、`cmake 3.22.0` + `cmake >= 3.25`（可用独立预编译包置于 `$WS/.reference/opengauss-native-lake/sdk/build-tools/bin/cmake`）、`python3`（`>= 3.10`）、`gcc/g++` 运行环境、`bison`/`flex`/`perl` 等。

   python3 -m pip install numpy==2.4.6 psycopg2-binary==2.9.12

4. 获取迁移后的 `openGauss-server` 代码到 `$WS/.worktrees/opengauss-native-lake`（检出 `codex/migrate-native-lake`，并确认 `contrib/og_lake/pq/isolate_pq_symbols.sh` 具备 `+x` 权限）：

### 4.4 第 3 步：编译与安装 openGauss 主程序（Make 与 CMake 双路径）

> [!CAUTION]
> **Make 与 CMake 不能混用同一份脏工作树**！`configure + make` 会在源码树内原地生成 `config.status`、`src/Makefile.global`、`src/include/pg_config.h`（且未定义 `ENABLE_HTAP`）；若在同一目录先后跑 Make 与 CMake，需先对非追踪构建生成物执行清理，或分别使用独立工作树（例如源码副本）。

#### 路径 1：推荐的 `configure + make` 链路（对应三画像验收口径）

准备通用依赖环境变量：
```bash
export WS=/path/to/cpp
export CODE_BASE="$WS/.worktrees/opengauss-native-lake"
export BINARYLIBS="$WS/binarylibs"
export GCC_PATH="$BINARYLIBS/buildtools/gcc10.3"
export OG_LAKE_ROARING_INCLUDE="$WS/.install/opengauss-native-lake-roaring-oom-component/native_bitmap_roaring_oom_repro_01/include"
export OG_LAKE_ROARING_ARCHIVE="$WS/.install/opengauss-native-lake-roaring-oom-component/native_bitmap_roaring_oom_repro_01/lib64/libroaring.a"
export OG_LAKE_PQ_IN_TREE=1
export OG_LAKE_PQ_BLAS_INCLUDE="$WS/.install/opengauss-native-lake-pq-openblas/pq_openblas_locking_build_repro_01/include"
export OG_LAKE_PQ_BLAS_ARCHIVE="$WS/.install/opengauss-native-lake-pq-openblas/pq_openblas_locking_build_repro_01/lib/libog_lake_pq_openblas.a"
export OG_LAKE_PQ_BLAS_LICENSES="$WS/.install/opengauss-native-lake-pq-openblas/pq_openblas_locking_build_repro_01/licenses"
```

- **Release (`-O2`) 编译与安装**（对应 `build_release.sh` 口径，设 `GAUSSHOME="$WS/.install/opengauss-native-lake-release"`）：
  ```bash
  export PATH="$GCC_PATH/gcc/bin:$PATH"
  export LD_LIBRARY_PATH="$GCC_PATH/gcc/lib64:$GCC_PATH/isl/lib:$GCC_PATH/mpc/lib:$GCC_PATH/mpfr/lib:$GCC_PATH/gmp/lib:${LD_LIBRARY_PATH:-}"
  cd "$CODE_BASE"
  env CC=g++ CFLAGS='-O2' LDFLAGS="-L$GCC_PATH/gcc/lib64" \
    ./configure --gcc-version=10.3.0 --prefix="$GAUSSHOME" --3rd="$BINARYLIBS" \
      --enable-thread-safety --without-readline --without-zlib --without-libxml
  make -sj"$(nproc)"
  # 若目标目录已装过一次，提前对只读 jre 补写权限：
  [ -d "$GAUSSHOME/jre" ] && find "$GAUSSHOME/jre" -type f ! -writable -exec chmod u+w {} + || true
  make install -sj1
  ```
- **Debug (`-O0`) 编译与安装**（对应 `opengauss_build_install_restart.sh` 口径，将 `CFLAGS='-O2'` 改为 `CFLAGS='-O0'` 并增加 `--enable-debug --enable-cassert`，装至 `GAUSSHOME="$WS/.install/opengauss-native-lake-debug"`）。
- **注意事项**：
  - 安装 `contrib/shark` 时会改写 `contrib/shark/smartmatch.pl` 权限位，安装后用 `chmod` 复原以免 git diff 出现噪声。
  - 若使用 `integration/opengauss-native-lake/build_driver.py ... --pq-in-tree --blas-build ...`，需注意该脚本中 `roaring_inputs()`、`blas_inputs()`、`pq_in_tree_inputs()` 会强校验收据 JSON 中的固定 SHA/path。

#### 路径 2：`CMake` 构建链路（已实测 `CMake 3.22.0 + GCC 10.3.0` Release）

保证 `$SRC` 目录无 `make` 残留（`config.status` / `pg_config.h` 等），配置同上 `OG_LAKE_PQ_*` / `OG_LAKE_ROARING_*` 后执行：
```bash
export CC="$GCC_PATH/gcc/bin/gcc"
export CXX="$GCC_PATH/gcc/bin/g++"
export THIRD_BIN_PATH="$BINARYLIBS"
export PREFIX_HOME="$WS/.install/opengauss-native-lake-cmake-test"
export DEBUG_TYPE=release
export BUILD_TUPLE=x86_64
export GCC_VERSION=10.3.0

cmake -S "$CODE_BASE" -B "$WS/.build/opengauss-native-lake/cmake_release" \
  -DENABLE_MULTIPLE_NODES=OFF -DENABLE_PRIVATEGAUSS=OFF \
  -DENABLE_THREAD_SAFETY=ON -DENABLE_MOT=OFF -DENABLE_HTAP=OFF \
  -DENABLE_READLINE=OFF -DUSE_LIBXML=OFF \
  -DENABLE_OPENEULER_MAJOR=ON -DENABLE_OPENSSL3=ON \
  -DCMAKE_BUILD_TYPE=Release
cmake --build "$WS/.build/opengauss-native-lake/cmake_release" -j"$(nproc)"
cmake --install "$WS/.build/opengauss-native-lake/cmake_release"
```
> 注：当前仅实测验证过上述 CMake `Release` 组合（`-DENABLE_HTAP=OFF`）；CMake `Debug` 组合未在此轮实测。

## 3. 必须保持的产品方向与工作边界

完整设计和历次问题结论分别在[架构与实施设计](架构与实施设计.md)和[设计问题与决策汇总](设计问题与决策汇总.md)，不要另创互相矛盾的架构。

- 保留openGauss原生**行执行器**，复用其优化器、事务、TableAM／IndexAM与SMP；Parquet列式存储不意味着把执行器改成列执行器。
- 采用DuckLake 1.1的数据库目录管理思路，不把DuckLake说成Iceberg。目录SQL／SPI与数据扫描、文件选择、版本／删除可见性是不同职责；读取inline业务行走原生访问路径。
- 逻辑行标识必须跨flush／重写稳定，并发修改保持原生RC等待、最新版本重取／EPQ语义。
- 文件索引、DiskANN及PQ／量化缓存复用已有接口与覆盖／回退合同；保持DiskANN主路线。
- 文件分区能力对齐pg_lake；数据库原生分区维持openGauss现状。

## 4. 本轮闭合的关键技术要点（0.54～0.56）

### 4.1 单次调用内 `LakeValidationScope` 元数据快径（0.54／0.55／0.56 已合入）

在 Debug `-O0` 下，单条事务提交（`LakePublishInlineChanges`）或单次查询绑定校验可能触发数十次 `LakeInstalledVersion()` 与 `LakeMetadataOwner()` SPI 查询。已合入的 `LakeValidationScope` 严格限定在单次内核入口的 `PG_TRY / PG_CATCH` 作用域内缓存扩展版本与内部 owner OID，并在子事务回滚（`LakeHostSubTransactionAbort`）、事务结束（`LakeHostTransactionEnd`）及 `DROP EXTENSION` 作用域切换时立即失效，零跨语句残留，使多轮 `flush`／`rewrite`／DDL 回归在 60s SQL 预算内稳定完成。

### 4.2 Public0.55 公开快照元数据与 O10 独立终验

`og_lake.current_snapshot(name)` 与 `og_lake.snapshots(name)`（7列：`snapshot_id`、`snapshot_time`、`schema_version`、`changes`、`author`、`commit_message`、`commit_extra_info`）按 `STABLE`、调用者权限、`NOT FENCED`、`search_path=pg_catalog,pg_temp`、管理员与 `READ COMMITTED` 串行后端门禁实现，512行 keyset 分批读取并过滤本事务未提交DDL历史。10模式套件在保留第22轮（DuckDB CLI `-json` 将 `UBIGINT` 序列化为字符串 `"0"`）与第23轮（第二 catalog 测试预建根目录与 openGauss `SET ROLE ... PASSWORD` 语法）原始失败现场后，于第24轮 `1117_04` 一次性通过受监督运行与 `independent_final_reader.py` 独立终验（`d8e0a2ad…`）。

### 4.3 SQL0.56 `last_committed_snapshot(name)` 与 `u_sess` 会话隔离

- **核心语义**：返回单列 `id bigint` 的单行结果集；当前数据库会话在当前绑定代数（`database_oid + server_oid + metadata_schema_oid + catalog_id + binding_generation + data_root`）下尚未成功提交过该 catalog 的湖快照时返回单行 `(NULL)`，一旦成功提交则返回本会话在该 catalog 上最后一次成功提交的快照号。
- **架构与异常安全**：状态挂在 `u_sess->og_lake_state`（`LakeHostSessionState::committed_catalogs`，位于 `u_sess->top_mem_cxt`），在提交前预分配会话节点与事务暂存槽位；`LakeHostTransactionEnd(true)` 提交尾阶段零内存分配、不抛错；未提交事务、`ROLLBACK`、`ROLLBACK TO SAVEPOINT`、空 `flush`／幂等 DDL（NOOP）及其他会话提交均不污染本会话返回值；`DROP SERVER` 与 `DROP EXTENSION` 提交后精确清除对应绑定状态（回滚则完整保留）。
- **覆盖全部10类发布器与线程池迁移**：[run_056_suite.py](验证/native_056_last_committed_22/run_056_suite.py) 在 `debug`（`enable_thread_pool=off`）、`debug`（`enable_thread_pool=on`，`thread_pool_attr='4, 1, (nobind)'`，9个并发客户端连接共享4个工作线程完成跨线程 `u_sess` 迁移，测后 `postgresql.conf` 原字节 SHA256 `e6e74fe8…` 已精确恢复）和 `ann-debug` 三组运行态全部通过 13 大类检查。

### 4.4 SQL0.57～SQL0.59 公开历史与管理视图总结（已完成）

- **`SQL0.57` `time_travel`（`b0a4e1f5…`）**：支持 `og_lake.time_travel(regclass, bigint / timestamptz)`（journal-free 只读历史快照视图，严格校验历史 schema 与 `FROM AS (...)` 返回定义，支持 15 种原生类型及跨 `flush`／`rewrite`／列演进，与 pinned DuckLake `AT (VERSION => ...)` 对拍一致）。

### 8.2 推荐先用交接文件，再按需只读查询

最简单的方式是直接读取本文件、`AGENTS.md` 与两份主设计文档；历史消息库只用于补充早期讨论背景，不推翻最新实际回执。按需只读查询示例（限定20条，不修改数据库）：

```python
from pathlib import Path
import sqlite3

root = Path('/home/qiumc/.codex-ali')
thread_id = '01a08e4f-df13-7702-af41-beab83658de7'
con = sqlite3.connect(
    (root / 'thread_history_1.sqlite').as_uri() + '?mode=ro',
    uri=True, timeout=3,
)
try:
    con.execute('PRAGMA query_only=ON')
    rows = con.execute("""SELECT item_type, item_json
                          FROM thread_items
                          WHERE thread_id = ?
                            AND item_type IN ('userMessage', 'agentMessage')
                            AND item_json LIKE ?
                          ORDER BY rollout_ordinal DESC
                          LIMIT 20""", (thread_id, '%flush%')).fetchall()
    for kind, payload in reversed(rows):
        print(kind, payload[:2000])
finally:
    con.close()
```
